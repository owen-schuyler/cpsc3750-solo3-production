Featured Project

Persistent Waters

Multi-phase Battleship-style web application

Persistent Waters lets players run a turn-based naval strategy match in the browser with persistent game state, firing feedback, and deployed phase builds. It is interesting because the project evolved from a backend API foundation into a playable web app while preserving server-side control over the rules. I kept game-state changes behind backend routes so turn validation, firing resolution, and match persistence stayed authoritative instead of being duplicated in client-side code.

Architecture Decision

Keep game rules authoritative on the backend

The most important design decision was to treat the Flask backend as the source of truth for match state, turn order, and firing outcomes. That kept the frontend focused on presentation and input while reducing the risk of inconsistent client-side game logic as the project moved through multiple phases.
